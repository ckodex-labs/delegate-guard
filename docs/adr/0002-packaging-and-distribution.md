# ADR-0002: Packaging, distribution, signing and air-gap delivery

- Status: accepted (2026-11-22)
- License: Apache-2.0. Ownership: own IP (namespace `ckodex`).

## Decision

All builds and packaging run in the Dagger pipeline (`ci/`, Dagger Rust SDK);
CI YAML only calls `dagger run cargo run --locked --manifest-path ci/Cargo.toml -- …`
(see the amendment below). Targets:

| Target | Tier | Notes |
| --- | --- | --- |
| `aarch64-apple-darwin`, `x86_64-apple-darwin` | 1 | Developer ID codesign + notarization for downloaded binaries |
| `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl` | 1 | static, used by packages and the OCI image |
| `x86_64-pc-windows-msvc` | 2 (Phase 6) | needs the Windows port first; Authenticode-signed |

Channels:

| Channel | Artifact |
| --- | --- |
| GitHub Releases | archives per target, `SHA256SUMS`, CycloneDX SBOM (syft), cosign keyless signatures + bundles, SLSA provenance |
| Homebrew tap | formula with a `service` block (Tier U via `brew services`) |
| Linux packages | `.deb` and `.rpm` (nfpm): binary, systemd user and system units (from `packaging/systemd/`; no socket activation, see the amendment below), `_delegateguard` user creation for Tier S |
| Claude Code plugin | `plugin/`: `hooks.json` wiring the client with `onFailure: "block"`; it installs configuration, not the binary |
| OCI | (a) distroless multi-arch image for the Linux daemon, socket on a volume; (b) OCI artifacts carrying the release bundle for registry mirrors |
| Air-gap bundle | one tarball: binaries, packages, SBOM, checksums, cosign bundles, the Sigstore trusted root used, a vendored source tarball (`cargo vendor`), offline verification instructions |

## Signing and secrets

- Keyless cosign from CI identity for public releases. For air-gapped
  verification the bundle carries cosign `--bundle` files and the trusted root,
  so `cosign verify-blob --offline` works with no network.
- Authenticode (Windows) and Apple Developer ID material is never placed in
  environment variables or CI variables. Signing runs out of band through
  `ck-vaultd` with a `CapabilityRequest`; the pipeline receives only the signed
  artifact and a receipt.

## Reproducibility

`--locked`, pinned toolchain image by digest, `SOURCE_DATE_EPOCH` from the commit,
`--remap-path-prefix`, no network during `cargo build` (vendored or fetched in a
separate cached step). Release builds keep `panic = "unwind"` and
`overflow-checks = true` (see README).

## Consequences

- Windows is a port, not a build flag: Unix sockets, file modes and `flock`
  callers need Windows equivalents (named pipes or `AF_UNIX`, ACLs,
  `LockFileEx`, a Windows service). It is scheduled after the Unix daemon is
  stable.
- Notarization and Authenticode need accounts and certificates that only the
  owner can provide; the pipeline stubs those steps until the vault capability
  exists.

## Amendment: generated code is checked in (2026-11-22)

Build-time code generation (protox + tonic-prost-build in a build script)
brought prost-build → petgraph → hashbrown → foldhash (Zlib) into the product's
build graph; petgraph 0.8.3 hard-enables hashbrown's `default-hasher`, so no
feature flag removes it. Instead, the admin API code is generated by
`tools/codegen` (a separate workspace with its own lockfile) and checked in at
`crates/admin/src/generated/`. The product's graph no longer contains protox,
prost-build, petgraph or foldhash, and `deny.toml` needs no exception. The
generator's own dependencies (foldhash included) are developer tooling, never
built into or alongside the product. The Dagger `codegen` gate regenerates and
diffs, so the checked-in copy cannot drift from `proto/`.

## Amendment: pipeline on the Dagger Rust SDK (2026-11-22)

The pipeline was first a Go-SDK Dagger module. It is now a Rust program on the
Dagger Rust SDK (`dagger-sdk` =0.21.12, matching engine v0.21.12), with its own
workspace and lockfile under `ci/`. Facts that shape it:

- The engine has no Rust module SDK: `dagger init --sdk=rust` fails with
  `invalid SDK: "rust"`. The Rust SDK is a client library, marked experimental
  in its upstream README. So the pipeline is a binary run under `dagger run`,
  not a module behind `dagger call`; there are no typed module arguments or
  function-level caching.
- The SDK connects to the session `dagger run` provides. Without one it
  downloads a Dagger CLI from the network (`dagger-sdk` `core/engine.rs`), which
  an air-gapped or pinned build must not do. The pipeline refuses to start
  (exit 69) unless `DAGGER_SESSION_PORT` is set; it checks presence only.
- The SDK reads its session token from the environment that `dagger run` sets.
  That is Dagger's design for every SDK; the pipeline itself reads no credentials.
- Client sessions use their own cache namespace, so the first run after the
  switch rebuilt every cache volume.
- The SDK's dependencies (about 200 crates, including rustls 0.21) stay in
  `ci/Cargo.lock`; none is built into or shipped with the product.

Verified 2026-11-22: all 8 gates pass on a clean tree (exit 0), and with one
planted formatting violation `fmt` and `clippy` fail and the run exits 1.
Re-check module support at each engine upgrade; the Go module is archived
outside the repository.

## Amendment: live-test image (2026-11-23)

The pipeline also builds the live-test image (`ci … live-image --out FILE`):
the pinned Node image plus Claude Code 2.1.330, jq, an unprivileged user and a
`delegate-guard` compiled from the workspace in the pinned Rust image,
exported with Docker media types. `scripts/live-matrix-smolvm.sh` boots each
test run from that local archive, because smolvm 1.6.8 enforces `--allow-cidr`
for image-based machines but ignores it for machines created from a packed
`.smolmachine`; the script refuses to run when its preflight VM can reach
`api.anthropic.com`. The image is test tooling, not a release artifact.

## Amendment: service units (2026-11-23)

Packages will ship the units in `packaging/` as `scripts/service.sh` fills them
in. They are not socket-activated: ADR-0001's phase 4 amendment records why. The
live-test image gained `acl` so `scripts/service-test-system.sh` can exercise the
sidecar ACL helper in a microVM.
